# AGENTS.md

This file provides guidance to AI agents when working with code in this repository.

## What this repository is

`simp-doc` holds the documentation source for SIMP. The pages are
reStructuredText under `docs/`, built with Sphinx and published to Read the
Docs. The repository also builds the `simp-doc` RPM.

## Read the style guide before you edit a page

`docs/contributors_guide/Documentation.rst` is the style guide for this
repository. Read the whole "SIMP documentation" section before you add or
change any page under `docs/`, and follow it. It covers:

- which role to use for packages, files, commands and Puppet modules
- file layout, page labels, heading order and line length
- how to write commands that work when copied and pasted
- how to check a technical claim before you write it down
- product, package and OS names
- links, the glossary, and pages that your page sends the reader to
- the checks to run before you submit

When a reviewer points out a problem that the guide does not cover, add the
rule to the guide in the same pull request.

## Layout

| Path | Contents |
|---|---|
| `docs/getting_started_guide/` | Installation and first setup |
| `docs/user_guide/` | Day-to-day administration |
| `docs/HOWTO/` | Task guides, grouped by topic |
| `docs/contributors_guide/` | Contribution, release and documentation procedures |
| `docs/FAQ/`, `docs/help/` | Questions and support resources |
| `docs/changelogs/` | Release notes; `latest.rst` is the working version |
| `docs/glossary.rst` | Every term that `:term:` can link to |
| `docs/_extensions/simp_roles.py` | The custom roles (`:package:`, `:pupmod:`, `:github:`) |
| `docs/conf.py`, `docs/conflib/` | Sphinx configuration and its Python helpers |
| `docs/dynamic/` | Generated by the build; not checked in |

Files that end in `.inc` are included by other pages and are not built as
pages of their own.

## Build and check

```sh
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
sphinx-build -n -b html -d sphinx_cache docs html
```

This is the command the "Build HTML docs" CI job runs. `bundle exec rake
docs:html` wraps it and runs a lint step first. The build reads the SIMP
version from `simp.spec` in simp-core. Set `SIMP_CORE_PATH` to a local
simp-core checkout to avoid the download.

CI does not pass `-W`, so a build with new warnings still passes, and a
reStructuredText error can drop content without failing. After a change:

1. Build `master` and your branch, and compare the warnings.
2. Open the changed pages in `html/` and check that they render as intended.
3. Run every command you added on each OS release the page covers.

The other CI jobs are the Python unit tests
(`pytest docs/conflib/get_simp_version_test.py`) and the RELENG checks
(`bundle exec rake pkg:check_version` and `pkg:create_tag_changelog`).
